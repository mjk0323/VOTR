# 아키텍처

## 개요

VOTR은 사용자의 노래를 분석해 보컬 코치 스타일의 리포트(잘한 점/고칠 점/현재 수준)를 생성하는 앱이다. 두 트랙으로 구성된다:

- **트랙 A (앱)**: `frontend/` (Next.js) + `backend/` (FastAPI) — 지금 동작하는 제품
- **트랙 B (ML)**: `ml/` — AI Hub "다음색 가이드보컬" 데이터셋으로 피치 추정/발성 기법 검출 모델을 학습하는 별도 파이프라인. 학습된 모델은 트랙 A의 DSP 휴리스틱을 대체한다.

## 하이브리드 DSP + LLM 설계

핵심 원칙: **LLM에게 원본 오디오를 직접 "듣고 판단"하게 하지 않는다.** 대신:

1. `backend/app/services/media_ingest.py` — 업로드된 오디오/영상을 mono WAV로 정규화 (imageio-ffmpeg)
2. `backend/app/services/audio_analysis.py` — librosa/parselmouth로 음정·박자·톤·다이나믹스를 객관적 수치로 계산
3. `backend/app/services/report_generation.py` — 계산된 수치(JSON)를 LLM에 전달, `docs/rubric.md`에 정리된 보컬 교육학 루브릭을 반영한 시스템 프롬프트로 정성적 리포트 생성 (JSON 스키마를 강제하는 구조화 출력으로 응답 확보)

이 3단계 경계가 명확히 분리되어 있어, 각 단계는 독립적으로 교체 가능하다.

## LLM 공급자 선택 (변경 이력)

`report_generation.py`가 어떤 LLM을 호출하는지는 세 번 바뀌었고, 매번 이유가 있었다:

1. **Claude API** — 최초 설계. 품질은 가장 좋았지만 유료(사용자가 API 크레딧을 구매할 자금이 없음)라 폐기.
2. **로컬 Ollama** (`qwen2.5:7b`) — 완전 무료, 인터넷/계정 불필요. 다만 사용자 노트북이 GPU가 없는 CPU 환경이라 리포트 1건에 1~2분씩 걸렸고, 무엇보다 **여러 사용자가 동시에 쓰는 공개 서비스로는 확장 불가능**(요청이 몰리면 그대로 줄줄이 밀림).
3. **Groq (현재)** — 무료 오픈소스 모델을 클라우드 LPU로 매우 빠르게 서빙. 무료이면서도 클라우드 기반이라 다중 사용자 배포가 가능해 지금 요구사항(비용 0원 + 공개 배포 목표)에 가장 잘 맞음. 다만 완전 오프라인은 아니고, 무료 정책이 향후 바뀔 수 있다는 리스크가 있음.

`generate_report(metrics)` 함수 하나로 진입점이 고정되어 있어서, 공급자를 다시 바꾸더라도 `report_generation.py` 내부만 교체하면 되고 라우터/프론트엔드는 영향받지 않는다. 완전 오프라인 개발/테스트가 다시 필요해지면 Ollama 경로(이 문서의 이전 버전, git 히스토리 참고)로 되돌릴 수 있다.

## 트랙 A → 트랙 B 교체 지점

`audio_analysis.py`의 `analyze_pitch()` 함수는 현재 `librosa.pyin` 기반 휴리스틱이다. 트랙 B(`ml/`)에서 AI Hub 데이터셋으로 학습한 싱잉 전용 피치 추정 모델과 비브라토/피치벤딩/브레스 검출기가 완성되면, 이 함수 내부 구현만 교체하면 된다 — `report_generation.py`, 프론트엔드, API 계약(스키마)은 그대로 유지된다. 자세한 모델 설계와 학습 파이프라인은 `docs/ml_pipeline.md` 참고.

## 향후 확장: 연습곡/유튜브 추천 (지금 미구현)

`backend/app/schemas/report.py`의 `VocalReport`에 향후 `recommendations` 필드를 추가할 자리를 주석으로 남겨두었다. 사용자의 선호 곡 스타일과 리포트의 `improvements`를 근거로 연습곡과 유튜브 영상을 추천하는 기능은 이 필드를 채우는 형태로 확장하면 되며, 지금의 파이프라인 구조를 변경할 필요가 없다.

## 데이터 저장

MVP는 별도 DB 없이 `backend/storage/{analysis_id}/`에 원본/정규화 오디오, `metrics.json`, `report.json`을 저장한다. 이력 조회 등 기능이 필요해지면 SQLite로 손쉽게 이전 가능한 구조다.

## 왜 유튜브 스크래핑 대신 AI Hub 라이선스 데이터셋을 쓰는가

유튜브 보컬 트레이너 영상을 다운로드해 학습에 쓰는 것은 이용약관 위반이자 저작권 침해 소지가 있어 채택하지 않았다. 대신:
- 루브릭(표준 보컬 교육학 지식, 일반 지식이라 저작권 이슈 없음)을 DSP 지표 설계와 LLM 프롬프트에 반영
- AI Hub에서 적법하게 신청·발급받은 "다음색 가이드보컬" 데이터셋(트랙 B)으로 실제 지도학습 진행

향후 추가 데이터가 필요해지면, 자체 사용자 동의 기반 수집이나 보컬 코치와의 공식 파트너십을 통해 확보한다.
